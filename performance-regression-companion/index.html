Unreal Engine 5.8 · Local performance testing

Performance Regression Companion

Did your content change make the scene slower? Save the test, record before and after, and compare the change against the noise between independent runs.

  • UE 5.8 · Win64
  • Native CSV Profiler
  • 5 repeats by default
  • C++ source included
  • Local reports

A decision after every content change

For artists and technical artists checking materials, effects, lighting and scene density. Companion repeats a saved fixed-camera test in separate Unreal processes, preserves the original captures and reports frame time, repeat spread and differences.

QuestionExperimentDecision
Is the new material too expensive?Capture the same view before and after the saved material edit.Compare frame p95 and GPU timing where available; inspect the images.
Did reducing light coverage help?Change only the intended light radii, keeping the profile fixed.Check measured change, noise and the visual tradeoff.
Can this VFX fit the frame budget?Record the controlled scene with both content versions.Inspect budget exceedance and native captures.

Install in the project you use

  1. Install for Unreal 5.8 from Fab, or copy PerformanceRegressionCompanion into YourProject/Plugins. Use one installed copy.
  2. Enable Performance Regression Companion in Edit → Plugins. Restart if requested.
  3. Open Tools → Performance Regression Companion. Check the project path at the top. The console command PRC.Open opens the same panel.

No web server, account, Python installation or Python editor plugin is needed. The worker uses Unreal's bundled Python. C++ source rebuilding requires the Unreal Windows toolchain.

Your first before / after comparison

  1. Click Open studio example & test profile. The included map opens with a saved camera. Accept the normal save prompt only after checking your unsaved work.
  2. Leave five repeats enabled. Enter the version name Original and click Run Baseline (before). Wait for the series to finish; game windows open and close in turn. Do not press Play.
  3. For an installation check, leave the scene unchanged. Enter Unchanged control and click Run Candidate (after).
  4. Choose those series in BEFORE and AFTER, then click Compare. An unchanged scene can still vary: a small difference inside observed noise should remain uncertain.
  5. For a content experiment, first duplicate the example map and materials into your project. Save a new profile for that map, record its baseline, edit the content, File → Save All, then record its candidate with the same profile.

The included studio is a small workflow example, not a hardware benchmark. Shader compilation and initial scene preparation can take longer than the recording itself.

Use your own scene

Open a saved map and position a perspective editor viewport. Click Use current map & view. Expand Edit test settings / advanced to name the profile and set warmup, duration, repeats, resolution, quality and frame budget; click Save.

Keep that profile unchanged across content revisions. Five repeats use five independent processes. Both versions need matching launch mode, hardware, rendering settings and capture options. VSync, FPS cap and dynamic resolution are recorded and controlled in the child session.

Render scene mode uses GameModeBase while level actors still simulate. Project game mode keeps your game simulation but fixes the view. Neither makes arbitrary gameplay deterministic.

Read the result

ResultMeaning
Regression / ImprovementThe median per-run p95 changed beyond the configured absolute, relative and observed-noise threshold.
UncertainThe difference is inside the threshold or observed noise. This is not proof of equal performance.
Limited comparisonConditions differ, repeats are incomplete or validation warnings prevent a definitive conclusion.
UnavailableThe native capture did not supply a usable metric. It is not zero.

p50 describes the middle of each frame distribution; p95 its slower tail. The comparison uses the median of the independent-run quantiles, not thousands of adjacent frames as independent experiments.

Threshold heuristic: max(minimum ms, baseline × minimum %, range A, range B, 2 × √(SD_A² + SD_B²)). This is a conservative heuristic, not a statistical significance test. Game, Render and GPU timings overlap and must not be added.

Go from a verdict to evidence

Open Capture opens the candidate's first Insights trace if recorded, otherwise its first CSV. Results Folder contains all repeats, engine logs, actual settings and checkpoints. Enable optional Insights before recording both series if you need matching traces.

A content note records your hypothesis. An optional BlueprintLogicScanner material Structured Diff can sit beside the result. A changed asset is an investigation candidate; correlation alone does not identify the cause.

Cancel keeps partial data. Failed and interrupted runs stay in history. Use Recover Interrupted after the previous worker and its child have stopped.

Keep the evidence with the result

Export Report creates a fresh folder and ZIP with both series, an HTML report, original captures, checksums and a standalone analyzer. Open Report/report.html offline. Run python reproduce.py with Python 3.10+ to regenerate analysis from the saved originals.

Working files live in Saved/PerformanceRegressionCompanion. Back up that folder before clearing Saved. Reports may include local paths and machine details: review them before sharing. Nothing is uploaded automatically.

Example: reduce unnecessary light coverage

A local test scene used 48 added lights. Reducing their radius from 2200 to 450 cm changed the median frame p95 from 29.12 to 16.10 ms across five processes per state. Repeat p95 ranges were 29.05–29.38 and 16.06–16.25 ms. The lighting appearance changed too: the faster variant requires an artistic review.

Archived measurement, 4 October 2026, Companion 1.0.1, UE 5.8.2 Development / Editor -game / DX12 / 1080p, RTX 5070 Ti Laptop and Core Ultra 9 275HX. Sequential runs; thermals and background load remain limitations. This example is not a promised speedup, a Shipping result or included third-party environment content.

Scope you can rely on

  • Windows, UE 5.8; tested with 5.8.2. Fixed-camera tests in separate UnrealEditor -game processes.
  • No packaged-build launcher, general replay automation, multi-device farm, automatic optimization or material cost prediction.
  • CSV profiling and optional Insights add overhead. Compare matching capture modes. Screenshots and CSV flushing happen after measurement.
  • Warmup does not guarantee shader compilation, streaming or simulation have settled. Inspect logs, pre-open the scene and keep background GPU work and power conditions stable.
  • Included: editor panel, runtime capture adapter, independent analyzer, studio map, three example materials and saved profile. Lyra, Liquid Props and paid environment packs are not included.
